How Façade-X works

Façade-X is the model SPARQL Anything uses to present every format in the same shape. It uses a small subset of RDF and no domain vocabulary, so the source content appears as it is. Your query then maps it to the ontology you need.

Containers
Each structure in the source becomes a container, a blank node: a table and its rows, a JSON object or array, an XML element. The outermost one is typed fx:Root.
Slots
Containers hold slots. Named parts, such as column headers, object keys and attributes, become properties in the xyz: namespace. Ordered parts, such as rows, array items and child nodes, become rdf:_1, rdf:_2 and so on.
Values
The content at the leaves becomes RDF literals, keeping the text as it appears in the source. Where the format says what a value is, it gets a datatype or a language tag: a JSON number becomes "1815"^^xsd:decimal, XML text under xml:lang="en" becomes "Ada"@en.
Types
Where the source gives a structure a name, such as an XML element or an HTML tag, the container gets that name as an rdf:type.
PREFIX fx:  <http://sparql.xyz/facade-x/ns/>
PREFIX xyz: <http://sparql.xyz/facade-x/data/>
PREFIX fxe: <http://sparql.xyz/facade-x/engine/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>

The Façade-X primer walks through the model with examples. The metamodel specification defines it formally, and the format mappings say how each format is represented.
